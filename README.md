# get_next_line

A C function that reads and returns one line at a time from a file descriptor.

## Description

The goal of this project is to implement a function capable of reading a file descriptor line by line without knowing the file size in advance.

The project introduces several important concepts in C programming, including:
- static variables
- dynamic memory allocation
- buffer management
- file descriptor handling
- memory safety

Repeated calls to `get_next_line()` return successive lines from a file descriptor until the end of the file is reached.

## Prototype

```c
char *get_next_line(int fd);
```


## How It Works

The implementation uses persistent buffered reading.
The function reads data from the file descriptor into a temporary buffer using the `read()` system call.

A static variable is used to preserve unread data between function calls, allowing the function to continue reading from the exact position where the previous call stopped.

The implementation follows these steps:

1. Read from the file descriptor into a buffer
2. Append new data to the saved static content
3. Extract a complete line if a newline is found
4. Save the remaining content for the next call
5. Return the extracted line


## Instructions

Compile with:

```bash
cc -Wall -Wextra -Werror -D BUFFER_SIZE=42 \
get_next_line.c get_next_line_utils.c
```

Example usage:

```c
int fd = open("file.txt", O_RDONLY);

char *line;
while ((line = get_next_line(fd)))
{
	printf("%s", line);
	free(line);
}
close(fd);
```

---
### Important

If `BUFFER_SIZE` is not defined in the compilation, it will have a default value of 10.

---


## Challenges

One of the main challenges of this project was correctly managing memory while preserving unread content between function calls.

Handling edge cases such as:
- very small buffer sizes
- files without newline characters
- multiple consecutive newlines
- invalid file descriptors

required careful buffer and allocation management to avoid memory leaks and undefined behavior.
